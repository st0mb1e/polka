# Полка

Простой сайт со списком книг для лабораторной работы. Каталог, личная полка и профиль открываются как отдельные страницы. Вход — через **Google OAuth 2.0 / OpenID Connect** (Authorization Code + PKCE S256).

## Что умеет приложение

- Показывает каталог из восьми книг в карточках с названиями, авторами и простыми цветными обложками.
- После входа сохраняет книги на личную полку со статусами «Хочу прочитать», «Читаю» и «Прочитано».
- Позволяет менять статус и убирать книги с помощью обычных HTML-форм.
- Показывает имя, логин и почту пользователя на отдельной странице профиля.
- Хранит личную коллекцию между входами и перезапусками сервера.

Каталог открыт гостям. Полка и профиль требуют авторизации. Навигация использует обычные ссылки: сервер возвращает отдельный HTML-документ для каждого адреса. OAuth временно переводит браузер на страницу провайдера и возвращает на запрошенную страницу.

## Технологии

Node.js, Express, express-session, openid-client, Helmet; обычные HTML и CSS без сборщика. Интерфейс состоит из верхнего меню, карточек книг, профиля и форм. Обложки оформлены текстом и CSS, шрифт — системный. На узком экране карточки идут в одну колонку. Клиентский JavaScript, внешние изображения и шрифты не используются.

HTML формируют функции в `src/views.js`, маршруты находятся в `src/web-app.js`, оформление — в `public/style.css`. Отдельного шаблонизатора нет. Динамические строки экранируются перед вставкой в HTML.

## Запуск

Требуется Node.js **22.20 или новее**.

Для nvm в `.nvmrc` указана версия Node.js **24**. Установите и выберите её из каталога проекта:

```sh
nvm install
nvm use
```

Затем установите зависимости и запустите приложение:

```sh
npm ci
npm run setup
npm start
```

Откройте **http://127.0.0.1:3000**. Команда setup создаёт `.env` со случайными секретами; существующий файл не перезаписывается. После изменения `.env` перезапустите сервер.

Адрес прослушивания задаётся переменной окружения `HOST`. По умолчанию используется `127.0.0.1`. Чтобы слушать все сетевые интерфейсы, добавьте в `.env`:

```dotenv
HOST=0.0.0.0
```

Или передайте переменную при запуске:

```sh
HOST=0.0.0.0 npm start
```

По умолчанию адрес сайта `appUrl` собирается как `http://HOST:APP_PORT`. Например, `HOST=127.0.0.1` и `APP_PORT=3000` дают `http://127.0.0.1:3000`. Явно задавать такой же `APP_URL` не требуется. Пустое значение использует автоматическую сборку, непустое — переопределяет её.

Переменная `APP_URL` позволяет указать адрес сайта отдельно от адреса прослушивания, например за обратным прокси:

```dotenv
HOST=0.0.0.0
APP_PORT=3000
APP_URL=https://polka.example
```

Указывайте полный адрес с `http://` или `https://`, без пути. Он используется для OAuth-переадресаций и проверки Origin. В настройках Google зарегистрируйте `${APP_URL}/auth/callback`. `polka.example` здесь обозначает ваш собственный домен: замените его на реальный. HTTPS обеспечивает обратный прокси на той же ВМ; само приложение продолжает слушать HTTP на `APP_PORT`. Прокси должен передавать `X-Forwarded-Proto: https`. Приложение доверяет этому заголовку только от loopback-адресов и при HTTPS использует Secure cookie.

`0.0.0.0` и `::` обозначают все сетевые интерфейсы. При таком `HOST` и пустом `APP_URL` для локальной работы используются соответственно `127.0.0.1` и `[::1]`. Google принимает HTTP только для localhost и loopback; для других адресов нужен HTTPS-домен. Адрес возврата с обычным IP, включая `10.9.0.1`, Google не разрешает даже с HTTPS. При заполненных Google-ключах приложение проверяет это при запуске и подсказывает, как исправить `APP_URL`.

В автономном режиме `issuer` аналогично собирается из `HOST` и `AUTH_PORT`; переменная `AUTH_URL` позволяет переопределить его отдельно. Адреса нормализуются: завершающий `/` убирается, стандартные порты сворачиваются. Пути, параметры, фрагменты, учётные данные и wildcard-адреса в `APP_URL` и `AUTH_URL` отклоняются.

В режиме Google запускается только веб-приложение. Если ключи не заполнены, публичные страницы работают, а вход возвращает HTTP 503. Метаданные Google загружаются при первом входе и кэшируются в процессе; временная недоступность Google не мешает открывать каталог. Перехода на учебную учётную запись автоматически нет.

## Подключение Google OAuth

1. Создайте или выберите проект в [Google Cloud Console](https://console.cloud.google.com/). В **Google Auth Platform** настройте название приложения и контактную почту. Для внешних пользователей выберите аудиторию **External**; если приложение находится в режиме **Testing**, добавьте свой Google-аккаунт в **Test users**.
2. В разделе [Clients](https://console.cloud.google.com/auth/clients) создайте OAuth client типа **Web application**. В **Authorized redirect URIs** добавьте:

   ```text
   http://127.0.0.1:3000/auth/callback
   ```

3. Приложение запрашивает только `openid profile email`. В **Data Access** укажите эти базовые разрешения; отдельные API Диска или почты для входа не нужны.
4. Скопируйте Client ID и Client secret в существующий `.env`, сохранив `SESSION_SECRET` и остальные сгенерированные значения:

   ```dotenv
   AUTH_PROVIDER=google
   GOOGLE_CLIENT_ID=идентификатор.apps.googleusercontent.com
   GOOGLE_CLIENT_SECRET=секрет_вашего_приложения
   ```

5. Перезапустите сервер и нажмите **Войти через Google**. Используйте обычный браузер. После входа откройте каталог, добавьте книгу на полку, измените статус и обновите страницу: книга должна сохраниться.

При изменении `HOST`, `APP_PORT` или `APP_URL` проверьте зарегистрированный Redirect URI: он должен точно совпадать с `${config.appUrl}/auth/callback`. `localhost` и `127.0.0.1` — разные адреса: используйте один и тот же адрес в браузере и настройках приложения. Client secret хранится только в `.env`, исключённом из Git. Токены приложение получает автоматически после входа.

При обновлении старой установки замените `AUTH_PROVIDER=yandex` на `AUTH_PROVIDER=google` и добавьте Google-ключи вручную: `npm run setup` не перезаписывает существующий `.env`. Сохранённые полки определяются провайдером и идентификатором пользователя. Записи Яндекса остаются в файле, а Google-аккаунту соответствует отдельная полка; автоматического связывания аккаунтов по почте нет.

Источники: [серверный OAuth и правила Redirect URI](https://developers.google.com/identity/protocols/oauth2/web-server), [OpenID Connect и проверка ID-токена](https://developers.google.com/identity/openid-connect/openid-connect).

## Запуск на ВМ с адресом 10.9.0.1

Для лабораторной работы можно открыть сервер через SSH-проброс на localhost браузера. На **серверной ВМ** укажите в `.env`:

```dotenv
HOST=10.9.0.1
APP_PORT=3000
APP_URL=http://127.0.0.1:3000
AUTH_PROVIDER=google
```

Заполните Google-ключи и запустите `npm start`. На **клиентской машине, где открыт браузер**, выполните:

```sh
ssh -N -L 127.0.0.1:3000:10.9.0.1:3000 имя_пользователя@10.9.0.1
```

Нужен работающий SSH-сервер на ВМ и свободный локальный порт 3000. Пока SSH-команда выполняется, открывайте сайт по `http://127.0.0.1:3000`. В Google зарегистрируйте `http://127.0.0.1:3000/auth/callback`. Браузеру и серверной ВМ нужен интернет для обращения к Google. В этом случае `APP_URL` указан отдельно, поскольку браузер открывает localhost, а сервер слушает адрес ВМ.

Другой вариант — свой HTTPS-домен с обратным прокси на ВМ и `APP_URL=https://ваш-домен`. Для него зарегистрируйте соответствующий HTTPS Redirect URI.

## Хранение и безопасность

Личные списки записываются в `.data/shelves.json`, исключённый из Git. Пользователь определяется сочетанием провайдера и подтверждённого OAuth-идентификатора, а не именем или почтой. Записи обновляются последовательно с атомарной заменой файла. Файл создаётся с правами `0600`. Каталог находится в `src/books.js`.

OAuth использует одноразовый код, PKCE S256, `state` и `nonce`. Google ID-токен проверяется через `openid-client`: подпись RS256 по ключам Google, issuer, audience, срок действия и nonce. Для входа требуется подтверждённая Google почта. Имя и email берутся из проверенного токена; учётная запись определяется по `sub`. Запрос входа действует 5 минут. Сессия меняет идентификатор после входа и действует до часа, не дольше срока ID-токена и access token. Google access token, ID-токен и секрет клиента не сохраняются в пользовательской сессии и не отправляются в браузер.

Все изменения полки и выход защищены CSRF-токеном и проверкой Origin. Формы и API полки принимают только известные книги и допустимые статусы. Cookie имеет HttpOnly и SameSite=Lax. Персональные ответы не кэшируются.

Кнопка «Выйти» вверху страницы уничтожает сессию приложения, сохраняя коллекцию. Сеанс Google в браузере остаётся открытым; следующий вход предлагает выбрать аккаунт (`prompt=select_account`).

По умолчанию сервис слушает `127.0.0.1` по HTTP для локальной демонстрации; адрес прослушивания можно изменить через `HOST`. Сессии хранятся в памяти и заканчиваются при перезапуске, книги — в файле. Для внешнего размещения потребуются HTTPS-прокси и постоянное хранилище сессий; Secure cookie включается автоматически при HTTPS в `APP_URL`. Файловое хранилище полок рассчитано на один процесс сервера.

## Адреса

| Адрес | Назначение |
| --- | --- |
| `/` | Каталог книг |
| `/shelf` | Личная полка, доступна после входа |
| `/profile` | Профиль пользователя, доступен после входа |
| `/dashboard` | Перенаправление на `/shelf` для старых ссылок |
| `POST /shelf/:bookId` | Форма добавления, смены статуса или удаления книги |
| `/api/books` | Публичный каталог |
| `/api/me` | Текущий пользователь; гостю HTTP 401 |
| `/api/shelf` | Личная полка; гостю HTTP 401 |
| `PUT /api/shelf/:bookId` | Добавление книги или смена статуса, JSON `{ "status": "planned" }` |
| `DELETE /api/shelf/:bookId` | Удаление книги с полки |
| `/auth/login` | Начало OAuth-входа |
| `/auth/callback` | Обработка ответа провайдера |
| `POST /auth/logout` | Выход с CSRF-токеном |
| `/health` | Проверка сервера |

Для изменений полки обязательны текущая сессия и Origin приложения. HTML-формы передают CSRF-токен в поле `csrf`, запросы к API — в заголовке `X-CSRF-Token`. В формах пустой `status` удаляет книгу с полки. После отправки формы сервер перенаправляет браузер на каталог или полку.

## Автономная проверка

Локальный OAuth 2.0 / OpenID Connect провайдер сохранён для проверки без внешнего аккаунта. Для его запуска явно установите в `.env`:

```dotenv
AUTH_PROVIDER=local
```

В этом режиме приложение работает на порту 3000, провайдер — на 3001. Логин и пароль находятся в `DEMO_USERNAME` и `DEMO_PASSWORD`. Локальные секреты создаёт setup. Этот режим использует `nonce`, ID-токен с проверкой подписи RS256 и выход из обеих сессий.

## Проверки

```sh
npm run check
npm test
```

Тесты проверяют оба OAuth-потока, отдельные страницы, закрытые API, PKCE, `state`, `nonce`, отказ в доступе, смену и срок сессии, CSRF, выход, сохранение личных списков, HTML-формы, параллельные изменения и разделение данных пользователей. Для Google используется имитация discovery и token endpoints с подписанными тестовыми ID-токенами и JWKS; проверяются также поддельная подпись, неверные issuer/audience/nonce, истёкший токен, отсутствие ID-токена и неподтверждённая почта. Реальный вход требует ключей Google. Тесты не читают `.env`; проверки изменения полки хранят данные во временном каталоге.

Снимки упрощённых страниц находятся в `docs/screenshots/simple-*.jpg`; подписи провайдера на них относятся к версии до перехода на Google. Файлы `simple-shelf-test.jpg` и `simple-profile-test.jpg` сняты на временном стенде с учебным аккаунтом. Снимки `polka-*.png` и пронумерованные файлы относятся к прежним версиям интерфейса. PDF-отчёт не создавался.
