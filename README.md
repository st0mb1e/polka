# Полка

Простой сайт со списком книг для лабораторной работы. Каталог, личная полка и профиль открываются как отдельные страницы. Вход — через **Яндекс OAuth 2.0** (Authorization Code + PKCE S256). Настройка VPN пока не выполнена.

## Что умеет приложение

- Показывает каталог из восьми книг в карточках с названиями, авторами и простыми цветными обложками.
- После входа сохраняет книги на личную полку со статусами «Хочу прочитать», «Читаю» и «Прочитано».
- Позволяет менять статус и убирать книги с помощью обычных HTML-форм.
- Показывает имя, логин и почту пользователя на отдельной странице профиля.
- Хранит личную коллекцию между входами и перезапусками сервера.

Каталог открыт гостям. Полка и профиль требуют авторизации. Навигация использует обычные ссылки: сервер возвращает отдельный HTML-документ для каждого адреса. OAuth временно переводит браузер на страницу провайдера и возвращает на запрошенную страницу.

## Технологии

Node.js, Express, express-session, openid-client, Helmet; обычные HTML и CSS без сборщика. Интерфейс состоит из верхнего меню, карточек книг, профиля и форм. Обложки оформлены текстом и CSS, шрифт — системный. На узком экране карточки идут в одну колонку. Клиентский JavaScript, внешние изображения и шрифты не используются.

HTML формируют функции в `src/views.js`, маршруты находятся в `src/web-app.js`, оформление — в `public/style.css`. Отдельного шаблонизатора нет. Динамические строки экранируются перед вставкой в HTML.

## Запуск

Требуется Node.js **22.20 или новее**.

```sh
npm ci
npm run setup
npm start
```

Откройте **http://127.0.0.1:3000**. Команда setup создаёт `.env` со случайными секретами; существующий файл не перезаписывается. После изменения `.env` перезапустите сервер.

Адрес прослушивания задаётся переменной окружения `HOST`. По умолчанию используется `127.0.0.1`. Чтобы слушать все сетевые интерфейсы, добавьте в `.env`:

```dotenv
HOST=0.0.0.0
```

Или передайте переменную при запуске:

```sh
HOST=0.0.0.0 npm start
```

По умолчанию адрес сайта `appUrl` собирается как `http://HOST:APP_PORT`. Например, `HOST=192.168.1.10` и `APP_PORT=3000` дают `http://192.168.1.10:3000`.

Переменная `APP_URL` позволяет указать адрес сайта отдельно от адреса прослушивания, например за обратным прокси:

```dotenv
HOST=0.0.0.0
APP_PORT=3000
APP_URL=https://polka.example
```

Указывайте полный адрес с `http://` или `https://`, без пути. Он используется для OAuth-переадресаций и проверки Origin. В настройках Яндекса зарегистрируйте `${APP_URL}/auth/callback`, например `https://polka.example/auth/callback`. HTTPS в этом примере обеспечивает обратный прокси; само приложение продолжает слушать HTTP на `APP_PORT`.

`0.0.0.0` и `::` обозначают все сетевые интерфейсы. При таком `HOST` и пустом `APP_URL` для локальной работы используются соответственно `127.0.0.1` и `[::1]`. Для доступа с другого устройства задайте `APP_URL` с реальным IP или доменом.

В автономном режиме `issuer` аналогично собирается из `HOST` и `AUTH_PORT`; переменная `AUTH_URL` позволяет переопределить его отдельно. Адреса нормализуются: завершающий `/` убирается, стандартные порты сворачиваются. Пути, параметры, фрагменты, учётные данные и wildcard-адреса в `APP_URL` и `AUTH_URL` отклоняются.

В режиме Яндекса запускается только веб-приложение. Если ключи не заполнены, публичные страницы работают, а вход возвращает HTTP 503. Перехода на учебную учётную запись автоматически нет.

## Подключение Яндекс OAuth

1. Создайте приложение для авторизации пользователей в [Яндекс OAuth](https://oauth.yandex.ru/client/new/id/). Назовите его «Полка».
2. Выберите платформу **Веб-сервисы** и зарегистрируйте Redirect URI:

   ```text
   http://127.0.0.1:3000/auth/callback
   ```

3. Включите разрешения **Логин, имя и фамилия, пол** (`login:info`) и **Адрес электронной почты** (`login:email`). Приложение использует идентификатор, логин, имя и почту.
4. Внесите Client ID и Client secret в локальный `.env`:

   ```dotenv
   AUTH_PROVIDER=yandex
   YANDEX_CLIENT_ID=идентификатор_вашего_приложения
   YANDEX_CLIENT_SECRET=секрет_вашего_приложения
   ```

5. Перезапустите сервер и нажмите **Войти через Яндекс**. После входа откройте каталог, добавьте книгу на полку, измените статус и обновите страницу: книга должна сохраниться.

При изменении `HOST`, `APP_PORT` или `APP_URL` проверьте зарегистрированный Redirect URI: он должен совпадать с `${config.appUrl}/auth/callback`. `localhost` и `127.0.0.1` — разные адреса: используйте один и тот же адрес в браузере и настройках приложения.

Источники: [регистрация приложения](https://yandex.ru/dev/id/doc/ru/register-auth), [получение кода и токена](https://yandex.ru/dev/id/doc/ru/codes/code-url), [API профиля](https://yandex.ru/dev/id/doc/ru/user-information).

## Хранение и безопасность

Личные списки записываются в `.data/shelves.json`, исключённый из Git. Пользователь определяется сочетанием провайдера и подтверждённого OAuth-идентификатора, а не именем или почтой. Записи обновляются последовательно с атомарной заменой файла. Файл создаётся с правами `0600`. Каталог находится в `src/books.js`.

OAuth использует одноразовый код, PKCE S256 и проверку `state`. Запрос входа действует 5 минут. Сессия меняет идентификатор после входа и действует до часа, не дольше срока токена. OAuth-токен и секрет клиента не сохраняются в пользовательской сессии и не отправляются в браузер. В режиме Яндекса профиль запрашивается через серверный API с заголовком `Authorization: OAuth ...`, проверяется `client_id`.

Все изменения полки и выход защищены CSRF-токеном и проверкой Origin. Формы и API полки принимают только известные книги и допустимые статусы. Cookie имеет HttpOnly и SameSite=Lax. Персональные ответы не кэшируются.

Кнопка «Выйти» вверху страницы уничтожает сессию приложения, сохраняя коллекцию. Сеанс Яндекса в браузере остаётся открытым; следующий вход запрашивает подтверждение (`force_confirm=yes`).

По умолчанию сервис слушает `127.0.0.1` по HTTP для локальной демонстрации; адрес прослушивания можно изменить через `HOST`. Сессии хранятся в памяти и заканчиваются при перезапуске, книги — в файле. Для внешнего размещения потребуются HTTPS, Secure cookie и постоянное хранилище сессий. Файловое хранилище полок рассчитано на один процесс сервера.

## Адреса

| Адрес | Назначение |
| --- | --- |
| `/` | Каталог книг |
| `/shelf` | Личная полка, доступна после входа |
| `/profile` | Профиль пользователя, доступен после входа |
| `/dashboard` | Перенаправление на `/shelf` для старых ссылок |
| `POST /shelf/:bookId` | Форма добавления, смены статуса или удаления книги |
| `/api/books` | Публичный каталог |
| `/api/me` | Текущий пользователь; гостю HTTP 401 |
| `/api/shelf` | Личная полка; гостю HTTP 401 |
| `PUT /api/shelf/:bookId` | Добавление книги или смена статуса, JSON `{ "status": "planned" }` |
| `DELETE /api/shelf/:bookId` | Удаление книги с полки |
| `/auth/login` | Начало OAuth-входа |
| `/auth/callback` | Обработка ответа провайдера |
| `POST /auth/logout` | Выход с CSRF-токеном |
| `/health` | Проверка сервера |

Для изменений полки обязательны текущая сессия и Origin приложения. HTML-формы передают CSRF-токен в поле `csrf`, запросы к API — в заголовке `X-CSRF-Token`. В формах пустой `status` удаляет книгу с полки. После отправки формы сервер перенаправляет браузер на каталог или полку.

## Автономная проверка

Локальный OAuth 2.0 / OpenID Connect провайдер сохранён для проверки без внешнего аккаунта. Для его запуска явно установите в `.env`:

```dotenv
AUTH_PROVIDER=local
```

В этом режиме приложение работает на порту 3000, провайдер — на 3001. Логин и пароль находятся в `DEMO_USERNAME` и `DEMO_PASSWORD`. Локальные секреты создаёт setup. Этот режим использует `nonce`, ID-токен с проверкой подписи RS256 и выход из обеих сессий.

## Проверки

```sh
npm run check
npm test
```

Тесты проверяют оба OAuth-потока, отдельные страницы, закрытые API, PKCE, `state`, отказ в доступе, смену и срок сессии, CSRF, выход, сохранение личных списков, HTML-формы, параллельные изменения и разделение данных пользователей. Для Яндекса тесты используют имитацию API, не реальный аккаунт; реальные ключи необходимо добавить отдельно. Тесты не читают `.env`; проверки изменения полки хранят данные во временном каталоге.

Снимки упрощённых страниц находятся в `docs/screenshots/simple-*.jpg`. Файлы `simple-shelf-test.jpg` и `simple-profile-test.jpg` сняты на временном стенде с учебным аккаунтом. Снимки `polka-*.png` и пронумерованные файлы относятся к прежним версиям интерфейса. PDF-отчёт не создавался.
